# Route B Fine-Grained Referring Expressions

This repository contains only Route B. It converts each English dense caption and source
image into automatically validated `(bbox, referring expression)` records for human review. Route A, C,
and D code, configuration, prompts, outputs, caches, model resources, and environments
have been removed.

```text
image + caption
  -> Qwen proposals (caption coverage first, then visual fill, 0–30 targets)
  -> Rex + SAM3.1 + GroundingDINO entity grounding
  -> multi-grounder consensus bbox candidates
  -> unique proposal alignment + bounded extra category-consensus promotion
  -> shared whole-object bbox verification for both target sources
  -> target-region OCR
  -> Qwen target-vs-distractor expression writing
  -> three-grounder expression re-ground
  -> deterministic and Qwen uniqueness verification
  -> at most two refinement/re-ground/re-verify rounds
  -> verified JSONL and one-box human-review JPGs
```

The input manifest is `data/manifest.jsonl` and contains 1,962 GPT-5.5-captioned source
images. Route B uses Qwen/Qwen3.8-27B, IDEA-Research/Rex-Omni, facebook/sam3.1, and
GroundingDINO-SwinB. Model inference requires a suitable NVIDIA GPU runtime.

The purpose is fine-grained object perception: an expression should identify one complete
object through visible distinguishing attributes and relations, rather than merely naming
its category. Automatic validation is not a guarantee of correctness; human review remains
necessary. The default run processes all 1962 source images in the current manifest: each
source may produce 0–30 accepted regions, each exported as a separate review image.

## How the pipeline works

| Stage | Input and operation | Output |
| --- | --- | --- |
| Selection | Sort manifest image IDs, shuffle with seed 42, select the requested slice | `outputs/route_b/selected_manifest.jsonl` |
| `entities` | Original image + caption; propose caption targets first, then visual-only objects (0–30 total); leave uncertain sizes to detection and recheck an empty response once | `outputs/route_b/entities.jsonl` |
| `ground` | Image + category queries to retrieve same-class objects; image + locator queries to retrieve the proposed target; run Rex, SAM3.1 and GroundingDINO | `outputs/grounder_outputs/route_b_entity_raw.jsonl` |
| `aggregate` | Deduplicate detections, build multi-model consensus and apply bbox size rules; retain peer information for comparison | `outputs/route_b/grounded_entities.jsonl` and grounding rejections |
| `align` | Qwen sees the original image, numbered candidate overlay and crop montage, with proposal/candidate cards; select one eligible matching instance or reject | `outputs/route_b/entity_alignments.jsonl` |
| `promote` | Inspect up to 16 additional unmatched category-only consensus candidates per image, without introducing new queries | `outputs/route_b/candidate_promotions.jsonl` |
| `bbox_verify` | Deduplicate aligned/promoted targets; verify the complete target, crop clarity and visible detail | `outputs/route_b/bbox_verifications.jsonl` |
| `ocr` | Qwen reads visible target-region text as supporting evidence | `outputs/route_b/region_ocr.jsonl` |
| `describe` | Qwen compares the target with distractors and writes a distinguishing English expression | `outputs/route_b/expression_drafts.jsonl` |
| `reground`, `expression_verify` | Re-ground image + expression using all three grounders; apply deterministic checks and Qwen visual uniqueness verification | Expression detections and `outputs/route_b/expression_verifications.jsonl` |
| `refine_*` | For eligible failures, revise the expression with the bbox fixed; re-ground and verify, at most twice | Refinement drafts, detections and verification records |
| `finalize`, `review` | Deduplicate and retain up to 30 verified targets per source; export every retained target | Final JSONL and one-box/one-expression JPGs |

Qwen instructions live in `prompts/route_b_*.txt`; the caller adds JSON task cards at
runtime. Inspect `src/routes/route_b_stages.py` for those cards and
`src/routes/route_b_discovery.py` for promotion. The main stage dispatcher is
`src/routes/route_b_caption.py`; managed execution is in `scripts/run_pipeline.sh`.

Proposal coverage is recorded in `outputs/route_b/entities.coverage.json`: image counts,
empty and invalid results, proposal-count distribution, and completed/recovered empty
rechecks. A high empty-answer rate produces a warning even when answers are valid JSON.
This does not change acceptance criteria. See `docs/ROUTE_B_DISCOVERY.md` for the policy.

## Data

The two root `sa_*.jsonl` annotation exports are included in Git (approximately
26 MiB each); images, Parquet files, weights, third-party checkouts, logs and generated
outputs are not. These are supplied annotation exports, not captions regenerated by
this repository. Their redistribution and the source image/model licenses must be
checked before publishing a copy of this repository.

The ModelScope dataset is intentionally retained as part of Route B's source-data
pipeline. The two annotation files `sa_000074.jsonl` and `sa_000523.jsonl` contain
22,366 successful GPT-5.5 captions. Route B matches their image IDs against the
`opensource_url` column of the ModelScope shard
`Tongyi-DataEngine/SA1B-Paired-Captions-Images/data/train-0000-of-0013.parquet`.
The intersection contains 1,962 images.

To reconstruct the dataset from scratch:

```bash
# 1. Download/verify the fixed ModelScope Parquet shard and record its schema.
source scripts/runtime.sh
export PYTHONPATH="$PWD"
python scripts/download_data.py

# 2. Match the GPT-5.5 annotations, download the source images, verify image size,
#    and write data/manifest.jsonl.
python \
  scripts/prepare_gpt55_route_b_data.py --output-dir data
```

The current preparation report is `data/download_summary.json`: all 1,962 matched
images were downloaded and validated, with zero failures. ModelScope's older
`global_caption` is retained only as manifest metadata; Route B uses the English GPT-5.5
`caption` field for entity proposal and expression generation.

## Configure and run

Install the workflow dependencies from `requirements/workflow.txt`. Model runtimes
are described in `requirements/environment_*.yml` and `docs/MODEL_SETUP.md`.
The default environment locations are `envs/<model>/bin/python`.

Machine settings belong in an external directory. Link that directory as `.local`
in your checkout; this directory is excluded from version control. Its optional
`runtime.sh` supplies shell environment variables, and `config.yaml` supplies
overrides keyed by repository config name:

```yaml
configs/models.yaml:
  rex:
    env_python: /your/environments/rex/bin/python
configs/experiment.yaml:
  dataset:
    download_dir: /your/data/downloads
```

Overrides merge recursively. Keep model versions, inference settings, prompts and
quality rules in the versioned configuration. `WORKFLOW_LOCAL_CONFIG` can select
a different override file; an explicitly selected missing file is an error.

Shell entry points accept `WORKFLOW_PYTHON`, `QWEN_ENV`, `QWEN_MODEL_PATH`,
`ENV_ROOT`, `MAMBA`, `HF_CLI` and `REGION_BENCHMARK_STORE`.
Credentials and generated runtime reports must remain outside version control.

With model resources and the GPU runtime ready:

```bash
bash scripts/run_pipeline.sh
```

The runner preserves the stage sequence and two refinement passes. It starts and
stops the Qwen service between model phases to release GPU memory. Range selection
uses `ROUTE_B_START_INDEX` and `ROUTE_B_END_INDEX` (defaults 0 and 1962).
Logs use `WORKFLOW_LOG_DIR` or `run_logs/`; `WORKFLOW_RUN_ID` labels the run.
A termination signal stops active work and exits with status 75; an external
supervisor may restart the runner to resume completed checkpoints.

Individual stages require their inputs and any model service to be ready:

```bash
bash scripts/run_route_b.sh --stage entities --resume --start-index 0 --end-index 100
```

`--stage all` on the Python entry point does not manage model services.
Use the managed runner when models share GPU memory.

CPU regression checks:

```bash
python scripts/check_route_b.py
python -m unittest discover -s tests
```

These checks do not establish GPU inference equivalence. Validate model execution
separately before relying on a new deployment.

## Outputs

Finalization/review also writes `outputs/verified_regions/route_b_counts_by_image.jsonl`:
one row per selected source, with `image_id` and `final_bbox_count`, including zero-result
images. This is a final-result summary, not a live count of intermediate candidate boxes.
Qwen parallel stages report processed/pending tasks and elapsed time (including 30-second
wait updates), grounders report request start/end, and review reports rendering progress.
Processed tasks can be accepted, rejected or failed; progress is not an acceptance count.

```text
outputs/
├── route_b/                         # structured intermediate audits
├── failures.jsonl                   # accumulated stage exceptions across runs
├── grounder_outputs/                # entity/expression/refinement detections
├── grounded_entities/artifacts/route_b/
├── entity_alignment/artifacts/route_b/
├── expression_verification/artifacts/route_b/
├── masks/B_caption/
├── verified_regions/route_b.jsonl
├── rejected_regions/route_b.jsonl
└── human_review/route_b/
    ├── index.csv
    └── *.jpg                         # exactly one bbox and one expression per JPG
```

The final review step uses `--overwrite`: it regenerates the review directory for the
current selected results. Do not store manual annotations or unrelated files there.
Inspect `index.csv` to map exported images back to their source/region records. Each JPG
has one bbox and one English expression in the upper-left; the same original may appear
in multiple JPGs with different targets. Intermediate JSONL files retain rejection and
verification details; the review count is not fixed at 100.

## Acceptance and recovery

### Single-target extent and evidence ownership

Bbox QA now requires both complete coverage and tight target extent, a single target,
and no unnecessary expansion to include neighboring entities. Incidental background or
occluding objects inside a necessary rectangular envelope are not automatically rejected.
It also records `target_evidence`: target properties/actions, separate reference objects,
verified relations, and uncertain attributes. Writer/refiner declarations select approved
evidence phrases; target text must come from target-associated OCR. The full generated
phrase is independently checked for property ownership, a single referring head, and
reference objects used only as relational anchors (including anchors outside the bbox).

For a complete but loose box, bbox QA can test at most two smaller alternatives derived
from existing cluster detections or mask envelopes. Alternatives must satisfy the original
size rules and retain multi-grounder IoU support; no VLM coordinates, arbitrary crop edits,
category-specific exceptions or new grounder calls are used. Each alternative must pass
all bbox/ownership checks. If none passes, the record is rejected. This bounded repair
cannot recover a precise box absent from the available detector/mask evidence.

Accepted repairs regenerate target crops and numbered views before OCR/writing. The new
geometry and evidence flow into checkpoint signatures, so downstream results cannot reuse
old-box conclusions. `bbox_repair_audit` preserves attempted boxes and decisions. Expression
re-grounding now requires IoU support and a symmetric area ratio no greater than
`aggregation.reground_max_area_ratio` (default 1.25); containment alone is insufficient.
Finalization/review require the new scope verification contract. Existing review images
are unchanged until rerun; old verified files cannot be re-exported as newly validated.
These are general rules, not special handling for particular images, colors or categories.

### Aggregation performance without changing acceptance rules

Aggregation now runs per image with a default of two workers (optional top-level
`aggregation_workers`, clamped to 1–4). It stores content-validated per-image results in
`outputs/route_b/aggregate_cache/`. Reuse requires matching proposal/detection records,
source image bytes, referenced mask bytes, manifest metadata, aggregation rules,
promotion setting, output root and relevant implementation code. Cached payloads have
checksums; missing/corrupt entries are recomputed. `--overwrite` bypasses reuse.
Hash checks still perform IO, so a cache hit is not free. Existing pre-optimization
outputs lack these signatures and require one aggregation rebuild.

`outputs/route_b/shared_instances.jsonl` indexes exact-coordinate shared instances and
their entity/query references. Existing candidate records retain their original IDs and
evidence for downstream compatibility, and add `shared_instance_id`; near-overlapping
boxes are **not** merged or moved by this optimization.

Candidate paths are planned at aggregation time, not eagerly rendered. Alignment still
sees the original image and its numbered candidate overlay/montage, including size-invalid
peers. Target overlay/tight/context images are materialized only for bbox verification or
promotion, shared for identical geometry, and repaired if missing/corrupt when requested.
Artifact generation permits at most two concurrent writers per process. No source-image
downscaling, bbox threshold, model query, or visual acceptance criterion was changed.

Synthetic CPU regression checks compare pre-change bbox/evidence records and rendered
JPEG bytes, cache reuse/invalidation and serial/parallel output equivalence. Full-dataset
wall-time, peak memory and shared-storage throughput improvements still require a real run;
do not infer a measured speedup from the worker count.

Qwen proposes both category queries (find same-class peers) and locator queries (find the
specific proposal); these are not a fixed category list. Caption is reference, not a gate.
At least two grounders must support a candidate. Consensus uses IoU 0.5 or containment
0.8 with area ratio at most 3. Boxes need a short side of at least 32 pixels and area
between 0.001% and 10% of the image. Whole-object verification, visible discriminative
attributes, re-grounding and uniqueness checks further restrict acceptance. Expressions
are English, 8–30 words, with at least two discriminative cues. All thresholds and prompt
paths are in `configs/route_b.yaml`; actual prompt texts are under `prompts/`.

Input image transport preserves decoded dimensions and uses PNG; the model processor
still applies its own constraints. Candidate montages and saved review artifacts are
derived visualizations, not replacements for the source images.

Resume reuses compatible completed records and grounding requests. Changed inputs/configs/
prompts can invalidate checkpoints, so resume does not mean blindly reuse everything.
Model outputs that remain invalid after bounded correction attempts are checkpointed
as skipped (`model_output_invalid_after_retries`), never accepted; network/server errors
still fail the stage. Failure of a job is distinct from automatic time-limit requeue:
fix the error and submit again to resume. Do not run multiple jobs against the same outputs.

### Unified model failure policy

All Qwen stages (proposal, alignment, promotion, bbox QA, OCR, expression writing,
verification and refinement) distinguish these outcomes:

- Valid visual rejection: retain the normal stage decision and continue.
- Invalid model JSON/schema or explicitly checked IDs/content: retry up to
  `qwen.max_attempts` total calls (default 3), with concrete correction feedback.
  Exhaustion writes a skipped checkpoint with `model_output_invalid=true`,
  `accepted=false`, `reject_reason`, `error_type` and `error_message`. It also logs to
  `outputs/failures.jsonl`. This is not a judgment that the object is unsuitable.
- Service/HTTP errors, OOM, unreadable files, unsupported configuration or unexpected
  program errors: log and fail the stage; cancel queued tasks. Already-running calls
  may take time to finish before the process exits. Grounder runtime errors also abort.

Skipped records stay in their own stage JSONL for resume, but are excluded from downstream
model inputs. Failed OCR prevents expression generation for that target rather than
pretending no text was present. Failed refinement retains the attempted revision's ID and
lineage so resume does not repeatedly generate it. Changed semantic inputs/prompts can
invalidate these checkpoints just as they invalidate successful records.

Each completed model batch writes `<stage-output-stem>.health.json` alongside its JSONL.
The `.out` prints a `WARNING` if all completed records are invalid, or at least 5 are
invalid and represent at least 10% of the stage output. This threshold is a warning,
not an automatic stop; inspect coverage before treating the dataset as ready. Individual
skips are auditable and are never counted as visually accepted targets.

Bbox requests explicitly distinguish the current entity ID from the retained candidate
instance ID. Promotion can create a new entity for an existing category-pool instance;
Qwen must copy the authoritative IDs, not derive one from the other's prefix.

Repository layout: `src/` implements the pipeline; `prompts/` defines Qwen tasks;
`configs/` holds dataset/model/threshold settings; `scripts/` handles setup, downloads,
checks and execution; `requirements/` contains dependencies/build patches; `docs/`
describes stage contracts; `artifacts/` contains local generated provenance/schema reports.
`data/` contains manifest metadata and untracked downloaded images. Runtime `outputs/`,
`models/`, `third_party/` and `run_logs/` are intentionally excluded from commits.

### Checkpoint history and diagnostic outputs

Route B keeps the active checkpoint for resume, but no longer creates full historical
checkpoint copies by default. Set `ROUTE_B_CHECKPOINT_HISTORY_LIMIT=N` to retain up
to N recognized historical copies per stage when a nonempty checkpoint is replaced.
The default is `0`; existing historical copies are left untouched in that mode.
Replacement is atomic, and historical pruning occurs only after a successful
replacement. A single update summary per stage in `checkpoint_updates/` records
counts and digests; it is diagnostic information, not a recovery checkpoint.

Promotion creates the highlighted numbered target image only for accepted targets.
The images supplied to the promotion model are unchanged, and accepted targets keep
the same numbered image for downstream stages.

`rejected_regions/route_b.jsonl` is now a compact rejection index containing available
image/entity/region/expression identifiers, revision, stage, rejection reason, and
`duplicate_of_region_id` where applicable. It no longer duplicates nested stage
payloads or intermediate image paths. Consumers that need detailed diagnostics
should read the corresponding stage checkpoints before intermediates are cleaned.
Accepted-result fields and acceptance rules are unchanged.
